Frequently Asked Questions

Why does Google Antigravity not show a Context Window bar by default?

Unlike single-loop CLI tools, Antigravity splits work across Planning and Execution phases in Orchestrator mode, isolates subagent sessions via invoke_subagent, and lazy-loads skills and MCP schemas. Antigravity still writes exact per-turn token counts to local session transcript.jsonl files, which Antigravity Context Monitor reads passively.

How are tokens calculated and attributed across categories?

Active session usage comes directly from the latest PLANNER_RESPONSE record: input_tokens + cache_read_tokens + output_tokens. The monitor reconciles 100% of that exact total across System & Rules, MCP Servers & Tools, Skills & Plugins, Files & Codebase, Terminal & Tasks, Chat Messages, and Reasoning & Subagents.

Is Antigravity Context Monitor safe for my account?

Yes. It operates strictly read-only on local transcript.jsonl files, makes zero network calls, never modifies API headers, prompts, or auth tokens, and enforces a strict 127.0.0.1 origin guard on all Electron IPC handlers.

Does it support 128k, 200k, and 1M context ceilings accurately?

Yes. All 18 official Antigravity models are mapped to their real context limits: 128k for GPT-OSS 120B, 200k for Claude Opus/Sonnet 5.5, and 1M for Gemini 3.8/4 and Orchestrator, with overflow alerts before handing a heavy session to a narrower model tier.
